Java — LuhnUtil.java (lines 17-40)
public static int calculateLuhnCheckDigit(String partial) {
    int[] digits = partial.chars()
        .map(c -> c - '0').toArray();
    int total = 0;
    for (int i = digits.length - 1; i >= 0; i--) {
        int d = digits[i];
        if ((digits.length - 1 - i) % 2 == 0) {
            d *= 2;
            if (d > 9) d -= 9;
        }
        total += d;
    }
    return (10 - (total % 10)) % 10;
}

public static String generateCardNumber(int sequence) {
    String seqStr = String.format("%09d", sequence);
    String partial = BIN_PREFIX + seqStr;  // "400012"
    int checkDigit = calculateLuhnCheckDigit(partial);
    return partial + checkDigit;
}
Algorithm Match: Both implementations iterate over the first 15 digits, double every alternate digit, subtract 9 if >9, sum all digits, and compute check = (10 - sum%10) % 10. BIN prefix "400012" is identical. Produces identical card numbers for the same sequence input.

public CardMaster activateCard(String cardNumber,
    String customerId, String pinOffset, String channel) {

    CardMaster card = cardRepo.findById(cardNumber)
        .orElseThrow(() -> new IllegalArgumentException(
            "Card not found: " + cardNumber));

    if (!"NW".equals(card.getCardStatus())) {
        throw new IllegalStateException(
            "Card must be in NW status to activate."
            + " Current: " + card.getCardStatus());
    }
    if (!card.getCustomerId().equals(customerId)) {
        throw new IllegalArgumentException(
            "Customer ID does not match card record");
    }

    card.setCardStatus("AC");
    card.setActivationDate(LocalDate.now());
    if (pinOffset != null) card.setPinOffset(pinOffset);
    CardMaster saved = cardRepo.save(card);

    recordHistory(cardNumber, prevStatus, "AC",
        "ACTIVATE", channel);
    return saved;
}
Validation Match: Both perform the same 3 checks: (1) card exists in DB, (2) status must be 'NW', (3) customer ID must match. Both set status to 'AC', record activation date, and save PIN offset. COBOL uses SQLCODE 0/100; Java uses Optional.orElseThrow().

public Map<String, Object> renewCards(int cutoffDays) {
    LocalDate cutoffDate =
        LocalDate.now().plusDays(cutoffDays); // 60

    List<CardMaster> expiringCards =
        cardRepo.findCardsForRenewal("AC", cutoffDate);

    for (CardMaster oldCard : expiringCards) {
        // Generate new card (shared sequence counter)
        int renewalSeq = sequenceCounter.getAndIncrement();
        String newCardNumber =
            LuhnUtil.generateCardNumber(renewalSeq);

        // Copy all fields to new card
        CardMaster newCard = new CardMaster();
        newCard.setCardNumber(newCardNumber);
        newCard.setCardType(oldCard.getCardType());
        // ... copy all fields ...
        newCard.setCardStatus("NW");
        newCard.setExpiryDate(
            LocalDate.now().plusYears(3));

        // Mark old card as expired
        oldCard.setCardStatus("EX");
        cardRepo.save(oldCard);
    }
}
Renewal Logic Match: Both: (1) calculate cutoff as today+60 days, (2) find 'AC' cards with expiry ≤ cutoff, (3) generate new Luhn card number, (4) copy all fields to new card with status 'NW', (5) set new expiry to +3 years, (6) mark old card as 'EX'. COBOL uses INTEGER-OF-DATE arithmetic; Java uses LocalDate.plusDays().

Status Code Note

IN (Inactive) Status: The COBOL copybook CPYCRD01.cpy defines an 'IN' (Inactive) status value at line 30. However, none of the actual COBOL programs (PICRD100-400) implement an AC→IN or IN→AC transition — this status was defined but unused in the POC. HL is a PICRD300 action code (88 WS-STS-ACT-HOTLIST VALUE 'HL'), but the COBOL program stores BL as the new status. The Java service and offline React fallback now preserve that behavior.
